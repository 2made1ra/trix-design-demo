# Демо-сайт TRIX: какие флоу покрыты

Фронт на Vue работает без бэкенда. Все запросы `/api/*` обрабатывает мок прямо в браузере (`src/mocks/router.ts`),
данные лежат в localStorage. Ссылка «Сбросить демо» в подвале возвращает данные к исходному сиду. Тестовые
аккаунты: `speaker@demo.trix` (спикер) и `admin@demo.trix` (админ организации).

## Гость

- **Развилка `/`** — выбор «Спикерам» или «Компаниям».
- **Лендинги `/speakers` и `/companies`.**
- **Страница мероприятия `/c/:slug`** — открыта без входа, кнопки зависят от того, вошёл ли пользователь.

## Спикер

1. **Регистрация и вход** (`/register`, `/login`). Ошибки показываются у каждого поля; если почта уже занята, рядом ссылка «Войти».
   API: `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/me`.
2. **Онбординг из трёх шагов** (`/onboarding/1..3`): сфера и опыт, цель и тема доклада, город, формат и «только оплачиваемые».
   Черновик сохраняется. При повторном входе ответы подставляются заново. Шаги можно пропустить.
   API: `GET/PUT /api/me/onboarding`, `POST /api/me/onboarding/skip`, справочники `GET /api/cities`, `GET /api/position-categories`.
3. **Подборка мероприятий** (`/events`): рекомендации под профиль, фильтры чипами, пустое состояние и состояние ошибки.
   Сверху показывается предложение выступить от организации, его можно принять или отклонить.
   API: `GET /api/me/recommendations`, `GET /api/cfps`, `GET /api/me/offers`, `POST /api/me/offers/:id/accept|decline`.
4. **Мероприятие** (`/c/:slug`): описание, треки, сроки. Подача заявки идёт либо через TRIX, либо через сайт организатора.
   API: `GET /api/conferences/c/:slug`, `GET /api/conferences/c/:slug/tracks`.
5. **Разбор доклада.**
   - `/talks/new`: загрузка PDF или вставка текста под выбранное мероприятие.
   - `/talks/:id`: этапы разбора («читаем → сверяем с аудиторией → готовим правки»), итог по критериям, правки, вопросы из зала, ошибка «текст не извлечён».
   - API: `POST /api/talk-reviews`, `GET /api/talk-reviews/:id`, фронт опрашивает его, пока разбор не закончится.

## Организация

1. **Заявка на подключение** (`/connect`): название, рабочая почта, сайт, согласие. После отправки — экран «Заявка принята».
   API: `POST /api/org/applications`.
2. **Приглашение администратора** (`/invite/:token`). Сценарии: новый пользователь (имя и пароль), уже вошёл, вход под другим аккаунтом, ссылка просрочена.
   API: `GET /api/invites/:token`, `POST /api/invites/:token/accept`.
3. **Онбординг организации** (`/org/onboarding/1..3`):
   1. Профиль: название, направления, города, домены почты.
   2. Импорт спикеров из таблицы. Модель задаёт вопросы по направлениям и почтам, потом показывает превью и рассылает приглашения.
   3. Приглашение коллег.

   API:
   - `GET /api/org`;
   - `PUT /api/org/onboarding/profile`;
   - `POST /api/org/onboarding/team`, `POST /api/org/onboarding/complete`;
   - импорт: `POST /api/org/speaker-imports`, `GET|DELETE /api/org/speaker-imports/:id`, `POST …/:id/answers`, `POST …/:id/send`.
4. **Спикеры организации** (`/org/speakers`).
   - Таблица или группировка по городам. Фильтры: поиск, направление, город, уровень, NPS, число выступлений.
   - Блок «Новое выступление на подтверждение»: оценка 1–5 и «Рекомендую».
   - API: `GET /api/org/speakers`, `GET /api/org/pending-talks`, `POST /api/org/pending-talks/:id/confirm`.
5. **Мероприятия организации** (`/org/events`): вкладки «предстоящие» и «прошедшие», добавление мероприятия по ссылке.
   API: `GET/POST /api/org/events`.
6. **«Кого позвать»** (`/org/events/:id/invite`): кандидаты под мероприятие и диалог «Предложить выступить» (трек, срок ответа, тема, сообщение).
   После отправки можно сразу посмотреть, как предложение увидит спикер (см. п. 3 у спикера).
   API: `GET /api/org/events/:id/candidates`, `POST /api/org/events/:id/offers`.

## Что важно для бэкенда

- **Уже есть в `api/openapi.yaml`** (клиент `src/api/generated.ts`):
  - авторизация;
  - `/api/me`, онбординг спикера, рекомендации;
  - справочники;
  - `/api/cfps`, мероприятие по slug.
- **В контракте нет, придумано на фронте.** Типы запросов и ответов лежат в `src/api/demo.ts`, логика мока — в `src/mocks/handlers/*`. Это кандидаты в контракт:
  - разбор доклада: `/api/talk-reviews*`;
  - заявка организации: `/api/org/applications`;
  - приглашения: `/api/invites/*`;
  - профиль и онбординг организации: `/api/org`, `/api/org/onboarding/*`;
  - импорт спикеров: `/api/org/speaker-imports*`;
  - спикеры и подтверждение выступлений: `/api/org/speakers`, `/api/org/pending-talks*`;
  - мероприятия и кандидаты: `/api/org/events*`;
  - предложения выступить: `/api/me/offers*`.
- Когда эти методы появятся в бэкенде, `src/api/demo.ts` заменяется сгенерированным клиентом. Страницы при этом не меняются.
- `POST /api/demo/reset` нужен только демо-сайту, в продукт он не идёт.
